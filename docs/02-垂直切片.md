# 对上了 · 垂直切片范围

> 本文只回答：这一刀切什么、不切什么、怎样才算切到。  
> 体验对错仍以 [00-体验目标.md](./00-体验目标.md) 为准。

---

## 1. 这一刀要验的一句话

没玩过的人打完这一局，能指着结算说：**「靠取消 / 摸鱼 / 请假这种词，把通知改了。」**

验不到这句话，切片失败。美术、平台、广告 SDK 都不在这一刀里。

## 2. 切进去的层

| 层 | 切到什么 | 本刀标准 |
|---|---|---|
| 规则 | 3 句通知、有序组对、四类结果、3 次组错、单句限时 | 纯逻辑可单测，状态机无 lane / leak / baseHp |
| 单局闭环 | 进纸面 → 对上三句 → 结算点名靠哪几对 → 再来 | 能赢能输能重开 |
| 十秒开场 | 0 秒就看见通知和字；第一次对上发生在 10 秒内 | 无菜单、无选关 |
| 语义演出 | 两个字撞成词，通知正文换句 | 色块 + 系统字即可 |
| 语序教学 | 反序给出「顺序反了」，正序才能改句 | 假请 / 消取 必须可复现 |

## 3. 这一刀明确不切

| 层 | 为什么现在不切 |
|---|---|
| 抖音包 / 真实广告 SDK | 微信包已按 code_1 同一套 runtime 先接上。抖音与广告播放这一刀仍不切 |
| 真实广告 SDK | 按钮位置按 2 个核心点留，不接播放 |
| 埋点上报 | 事件名按 01 节留下，切片只打 console |
| 局外进度 / 主题换皮 | 会抢走「对上」 |
| 立绘、棋盘、音效包 | 字就是美术 |
| 3–6 分钟完整句库 | 3 句够验密度；加长是后话 |

## 4. 切片内容（锁死）

主题：职场一天，8 句通知。第一句带手把手引导。

| 句 | 通知 | 要改掉的词 | 能对上的词 |
|---|---|---|---|
| 1 | 今晚全体加班 | 加班 | 取消 / 摸鱼 |
| 2 | 周会改到晚上 | 晚上 | 提前 / 取消 |
| 3 | 方案被毙了 | 毙了 | 能成 / 重来 |
| 4 | 客户说再改一版 | 再改 | 过了 / 定稿 |
| 5 | 午饭缩短十分钟 | 缩短 | 加长 / 取消 |
| 6 | 谁还没交点名 | 点名 | 已交 / 请假 |
| 7 | 明天继续 | 继续 | 放假 / 鸽了 |
| 8 | 全公司通宵 | 通宵 | 取消 / 放假 |

全局限 4 次组错。第一句 40 秒，其余约 32 秒。对上进入下一句。
界面必须让人看见：要改哪两个字、先/后槽、改完的新通知。

## 5. 怎样才算切到（验收）

1. 问「刚才怎么赢的」，答案里有具体两个字。
2. 至少能主动把一对反序纠正为正序。
3. 前 10 秒盲测：不会被说成塔防、合成、自走、消消。
4. `npm run build` 通过（类型 + 测试 + 产物）。

## 6. 计划（做完再给看）

1. 写下 00 / 01 / 02（本批）。
2. 写出 `PairEngine` 与三句词库，测试钉死四类结果和禁区字段。
3. 浏览器竖屏切片：纸面、字池、演出、结算、再来。
4. 按 code_1 接上微信小游戏 runtime / 适配层 / 组装脚本，产出 `build/wechat/`。
5. 用微信开发者工具打开该目录体验。能对上就停，不顺手加系统。
