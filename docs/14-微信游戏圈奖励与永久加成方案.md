# 14 · 微信游戏圈官方可核验奖励与 UI 规范（审查定稿版）

## 1. 微信官方 `wx.getGameClubData` 能力边界严格审查

为杜绝任何**无法核验、虚假达成或真机卡死领不到**的奖励设计，已逐项核查微信小游戏 SDK（`Packages/com.qq.weixin.minigame/Runtime/WX.cs`）与微信官方游戏圈加密数据文档：

| 指标 / 想法 | 微信官方 `dataTypeList` 类型 | 真机能否权威核验 | 审查结论与落地方式 |
|---|---|---|---|
| **加入微信游戏圈** | `type = 1`（加入该游戏圈秒级时间戳，`> 0` 即已加入） | **100% 权威可查**（老圈友打开即识别） | **保留为核心破冰大奖**（点击「前往游戏圈」不直接发奖，必须真实加圈后解密 `joinTime > 0` 才可领） |
| **每日进圈浏览 / 圈内签到** | 无对应 `type` | **不可核验**（微信不回传进圈浏览或圈内签到状态） | **彻底砍除**「前往游戏圈即发奖」与「每日进圈签到条」，绝不伪造前端假领奖 |
| **今日点赞 / 评论 / 发表帖子** | `type = 4 / 5 / 6`（自然日内点赞、评论、发表贴子数） | **100% 权威可查** | **保留为每日日常任务**（零点自动重置） |
| **累计点赞 1/3/5 次、累计评论 1/3/5 次** | 基于 `type = 4 / 5` 当日计数与存档当日基准做正向差值累加（`dayCount - ClubDayCount`） | **可稳健核验**（配合首页 `WX.OnShow` 后台静默同步） | **保留为三级前置解锁里程碑**；即使玩家去游戏圈互动后切回主页未点开弹窗，`GameClubWatcher.EnsureBackgroundHook` 也会自动同步当日增量 |
| **指定热帖点赞 / 评论（7~10）** | 需额外维护固定帖子 `gid` 且帖子删改即失效 | 易受运营删帖影响导致死任务 | **不采用**，统一使用无需绑定 `gid` 的全圈自然日互动（`1 / 4 / 5 / 6`） |

> **上线前微信公众平台必配项**：在 `mp.weixin.qq.com` →「设置 → 用户隐私保护指引」中勾选并声明收集 **【游戏圈信息】**。客户端已在打开游戏圈面板时主动调用 `WX.RequirePrivacyAuthorize`，在首页后台同步时先走 `WX.GetPrivacySetting`（未授权绝不弹骚扰窗），并在 `WX.CheckSession` 失效时自动重登刷新云端 `session_key`。

## 3. 顶级全手绘 UI 视觉规范（零程序绘制元素）

针对首版 UI 复盘，**100% 清零 `Art.Pill`、`Art.RoundedSmall`、`Art.VGrad` 等程序绘制色块与胶囊**：

1. **顶部鎏金原画框**：使用抽卡同款金属铆钉九宫格皮肤 `ui/gacha_dock_gold` 包裹 `club_banner.jpg`（智多星吴用 2.2 头身国风横幅，左下角直接由原画手绘朱红鎏金立体木匾呈现「游戏圈 · 每日福利领不停！」，无任何黑底渐变遮罩与程序胶囊覆盖）。
2. **中段木栓暖米挂板**：使用 `ui/quest_tray` 手绘挂牌皮肤，左侧 `slot_orange` 镶嵌宋江头像，中部双行说明入圈状态，右侧立体蓝钮「前往游戏圈」（真机叠放透明 `WXGameClubButton`）。
3. **下部标准三栏任务队列**：在 `ui/modal_well` 微凹槽内，与「每日任务 / 七日目标」100% 统一规格——`ui/row`、`ui/row_claim`、`ui/row_done` 三态手绘卡底（绝不乘算发脏灰泥色），左栏 3 枚 `92px` 品质槽道具，中栏粗黑标题 + `ui/bar_bg` 手绘进度条（未解锁态为 `ic_lock` 锁标 + 清晰前置任务名），右栏标准立体按钮。
4. **底部手绘挂签**：与「图鉴」同款采用 `ui/codex_btab_on` / `ui/codex_btab_off` 悬挂于弹窗底沿外侧，实现「每日福利 / 游戏圈」丝滑切换。
